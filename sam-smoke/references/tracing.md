# 灌煙規則

## 1. 證據來源

| 可以當依據 | 只能當線索 | 不可以用 |
| --- | --- | --- |
| 原始碼 | 註解 | README、規格、設計文件 |
| 建置設定（Makefile、Kconfig、專案檔、連結腳本、裝置樹） | 函式、變數、檔案的名稱 | commit 訊息、issue |
| 會被程式讀取的設定檔 | | 你對這類專案的一般印象 |

線索的意思是：可以幫你決定下一個該打開哪個檔案，但寫進步驟之前，一定要在程式碼裡看到。
註解說「已停用」而程式碼還在呼叫，就以程式碼為準。

## 2. 一步是什麼

**一步 = 煙進入專案自己寫的一個函式，而且這個函式改變了資料或狀態，或決定了接下來走哪條路。**

不算一步，併進上一步的 `desc`：

- 標準函式庫、框架、作業系統的呼叫（`memcpy`、`printk`、`JSON.parse`）
- 只讀不寫的小函式（取值、換算、格式化）
- 記錄訊息、參數檢查
- 同一個函式裡連續的小動作

一條旅程通常是 5 到 20 步。超過 40 步會被檢查擋下：先合併，合併不了再把後半段拆成另一個入口。

每一步的寫法：

- `title`：這一步做了什麼，動詞加受詞（「讀取觸控座標」）。不寫函式名稱。
- `desc`：怎麼做的，一到兩句。被合併的小動作寫在這裡。
- `file`、`line`、`symbol`：函式定義的位置，`symbol` 是那一行實際出現的文字（通常是函式名稱）。
  死路和霧的位置寫「出問題的那一行」，例如沒有接回傳值的呼叫、透過指標呼叫的那一行。

## 3. 順序與分岔

- 陣列順序就是煙走的順序，也是畫面由左到右的順序。
- A 呼叫 B，B 返回後 A 再呼叫 C：寫成 A、B、C 三步，不用 `from`。
- `from` 只用在兩種情況：
  1. **條件分岔**：`if`、`switch` 讓煙走向不同的路。每條路都要走。先走短的，走完再用 `from` 回到分岔點走另一條。
  2. **折返**：上一步是終點、死路或霧，煙回到前面某一步繼續走。

錯誤處理的分支：只回傳錯誤碼就結束的，寫進 `desc` 即可；有做實質動作的（回復、重試、通知）才畫成一條路。

迴圈和遞迴只畫一次，在 `desc` 註明「對每一筆重複」。

## 4. 煙怎麼停下

每條路的最後一步一定是下面三種之一，而且要寫 `reason`。

### 終點 `end`：正常結束

- 回到呼叫者（框架、作業系統、事件迴圈），沒有後續
- 把結果送到外面：寫檔、寫暫存器、送出封包、回報輸入事件、更新畫面
- 交給另一個入口：排進工作佇列、設定計時器、發出事件。這條旅程在這裡結束，
  `reason` 寫「交給入口『○○』」，另一邊當成獨立的入口來灌

### 死路 `dead`：走得到，但白走

- 被呼叫了，回傳值沒有人用
- 算出來或寫進去的變數，後面沒有人讀
- 呼叫的函式是空的，或只有 `return`
- 結果馬上被後面的另一條路覆蓋（新舊路徑並存）
- 分支的條件從程式碼看永遠不成立（常數、被寫死的旗標）

`reason` 要寫出證據位置，例如「validate.js 第 6 行沒有接收回傳值」。
只寫事實，不寫「應該刪除」這類判斷。

### 霧 `fog`：讀程式碼無法確定

- 透過函式指標、回呼表、操作表呼叫
- 介面或虛擬函式有多個實作
- 用字串組出名稱再呼叫、反射
- 巨集展開後才知道呼叫誰
- 條件編譯，無法確定哪一段生效
- 目標在專案之外：另一個行程、外部服務、沒有原始碼的函式庫

**先試著把霧吹散再決定：** 搜尋這個指標或表格在哪裡被賦值。

- 整個專案只有一個賦值處：不是霧。直接走進那個函式，並在 `desc` 註明「經由 ○○ 指標，唯一賦值在 file:line」。
- 有多個賦值處，或找不到：是霧。`reason` 寫出你找到的候選（最多三個）和無法確定的原因。

不確定時選霧。把霧畫成確定的路，比留下霧更糟。

## 5. 追蹤一個入口的做法

1. 打開入口的處理函式，從第一行讀到最後一行。
2. 遇到專案自己的函式呼叫，打開它的本體，判斷算不算一步（第 2 節）。
3. 算一步就記下來，再往它裡面讀，直到碰到終點、死路或霧。
4. 回到上一層，繼續讀下一行。
5. 遇到條件分岔，記下分岔點，每條路都走。
6. 處理函式讀完，確認每條路的最後一步都有交代。

## 6. 寫完自我檢查

- 每一步我都打開過函式本體嗎？有沒有哪一步是看名稱寫的？
- 有沒有哪個函式指標或回呼，我直接當成確定的路？
- 有沒有哪一步的內容其實來自文件或註解，而不是程式碼？
- 死路的 `reason` 有寫出證據在哪一行嗎？
- 入口的處理函式，我讀到最後一行了嗎？
