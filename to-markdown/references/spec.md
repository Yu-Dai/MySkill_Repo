# ToMarkdown 輸出規格

這份規格定義「轉完應該長什麼樣」，也是驗收標準。實作要對齊這裡，不是反過來。

目的：轉出的 Markdown 給 LLM 建知識庫用。判斷取捨時以「LLM 檢索與閱讀」為準，不以人眼排版為準。

## 狀態

| 格式 | 狀態 |
|------|------|
| xlsx | 已實作（圖表資料序列尚未做） |
| csv | 已實作 |
| docx | 已實作 |
| pptx | 已實作（投影片截圖只能在 Windows 執行，尚未實機驗證；圖表資料尚未做） |
| pdf | 已實作快速模式。用 5 份公開的 datasheet 與使用手冊測過 |
| xls、xlsb、ppt、pps、doc、rtf | 不支援。腳本會提示使用者自己另存成新格式 |
| 精準模式（看圖） | 已實作，只用本機模擬的 API 測過，尚未接真正的模型 |

## 共通規則

### 輸出位置

```
輸出資料夾/
  檔名.md
  檔名_assets/        只有來源含圖片或截圖時才建立
    img-001.png
    page-003.png
    slide-05.png
```

- 圖片一律存成旁檔，Markdown 內只放相對連結。不內嵌 Base64：它會吃掉大量 token，也會破壞知識庫的切塊。
- 相同內容的圖片只存一份（以內容雜湊判斷）。
- 同一批裡有同名但格式不同的檔案時，輸出檔名加上格式：`report_docx.md`、`report_pdf.md`，資料夾也是 `report_docx_assets/`。

### 檔頭

每個檔案以 YAML front matter 開頭：

```markdown
---
source: "register_map.xlsx"
type: xlsx
converter: "to-markdown 0.1.0"
mode: fast
---
```

各格式可再加自己的欄位（例如 xlsx 的 `sheets`）。不寫轉檔時間，這樣同一份來源重轉的結果完全相同，方便比對差異。

### 分段與來源定位

- 分段一律用 Markdown 標題，因為切塊工具依標題切。
- 每段都帶來源定位：xlsx 是 sheet 名稱與儲存格範圍，pdf 是頁碼，pptx 是投影片編號。

### AI 產生的內容

精準模式下由模型寫出的文字，一律用引言區塊並加固定標記，後面保留原圖連結：

```markdown
> [AI 描述，請對照原圖] 這張圖是開機流程……
> [AI 轉寫，請對照原圖]
```

模型轉寫十六進位與位元欄位可能出錯，所以這類內容不可與腳本抽取的內容混在一起。

### 模式

| | 快速 fast（也可寫 flash） | 精準 precise |
|---|---|---|
| 文字、表格 | 腳本抽取 | 同左 |
| 圖片 | 存檔＋連結 | 存檔＋連結＋AI 描述 |
| 腳本處理不了的頁面 | 截圖連結＋標記 | 截圖連結＋AI 轉寫 |
| 需要 API | 否 | 是 |

## xlsx

```markdown
---
source: "register_map.xlsx"
type: xlsx
converter: "to-markdown 0.1.0"
mode: fast
sheets: ["Register", "Protocol"]
hidden_sheets_skipped: ["tmp"]
---

# register_map.xlsx

## Sheet: Register

### Table 1 (A1:F12)

**Touch IC Register Map**

| Addr | Name | Bit | Field / Name | Field / Default |
|------|------|-----|--------------|-----------------|
| 0x1F | CTRL | 7:4 | MODE | 0x0 |
| 0x1F | CTRL | 3:0 | GAIN | 0x3 |

![圖片（錨定 H3）](register_map_assets/img-001.png)

**儲存格註解**

- C5：保留位元，寫入時必須為 0
```

規則：

1. **合併儲存格：** 拆開後把左上角的值填滿範圍內每一格。這樣每一列都自帶位址與名稱，檢索切到任何一列都看得懂。
2. **多列表頭：** 壓平成單列，上下層用 ` / ` 連接（例如 `Field / Default`）。判斷依據是表頭列的合併儲存格。
3. **一個 sheet 多張表：** 以整列空白、整欄空白切開，各自輸出成一張表，標題帶儲存格範圍。
4. **表格標題列：** 表格上方橫跨整張表的單一文字，輸出成表格前的粗體字，不放進表格。
5. **只有一欄的區塊：** 視為說明文字，逐列輸出成段落，不做成表格。
6. **數值取顯示值：** 套用儲存格的數字格式（補零、小數位數、百分比、千分位、日期、前後綴文字），不輸出底層數值。公式取 Excel 存下的計算結果。
7. **日期：** 一律輸出成 `YYYY-MM-DD`、`YYYY-MM-DD HH:MM`。
8. **隱藏的 sheet：** 預設略過，名稱列在檔頭的 `hidden_sheets_skipped`。隱藏的列與欄照常輸出。
9. **儲存格註解：** 列在該 sheet 最後。
10. **圖片：** 存成旁檔，連結放在錨定位置所屬的表格之後，並標註錨定的儲存格。
11. **儲存格內換行：** 轉成 `<br>`。`|` 轉成 `\|`。

已知限制：

- 圖表目前不輸出（規劃輸出標題與資料序列）。
- 表格中間若有整列空白，會被切成兩張表，第二張表沒有表頭。
- 公式若沒有儲存計算結果（檔案由程式產生、從未用 Excel 開過），該格為空，轉檔時會列出警告。
- 少見的數字格式（分數、科學記號、條件格式）以一般數值輸出。

## csv

```markdown
---
source: "log.csv"
type: csv
converter: "to-markdown 0.1.0"
mode: fast
encoding: "cp950"
delimiter: ","
---

# log.csv

### Table 1 (3 欄 × 120 列)

| time | addr | value |
|------|------|-------|
```

規則：

1. **編碼：** 依序嘗試 BOM、UTF-8、Big5（cp950）。偵測結果寫進檔頭。
2. **分隔符號：** 自動判斷逗號、分號、Tab、`|`。
3. **第一列當表頭。** 欄數不齊的列補空白。

## docx

```markdown
# driver_guide.docx

**Demo Touch Driver 使用說明**

## 1 概述

本文件說明初始化流程。

1. 上電並等待 10 ms
1. 讀取 CHIP_ID

| Addr | Name | Field / Bit | Field / Default |
|---|---|---|---|
| 0x1F | CTRL | 7:4 | 0x0 |

![圖片](driver_guide_assets/img-001.png)
```

規則：

1. **標題：** 檔名佔用第一層 `#`，所以 Word 的「標題 1」輸出成 `##`，依此類推。「Title」樣式輸出成粗體字。
2. **清單：** 項目符號輸出成 `-`，編號清單一律輸出成 `1.`，階層用縮排表示。
3. **表格：** 合併儲存格、多列表頭的處理同 xlsx。只有一欄的表格視為排版用外框，直接輸出內容。
4. **圖片：** 存成旁檔，連結放在原本的位置。有替代文字時當作圖片說明。
5. **文字方塊：** 內容輸出在所在段落之前。
6. **超連結：** 輸出成 `[文字](網址)`。
7. **追蹤修訂：** 取接受後的結果（新增的保留，刪除的略過）。
8. **略過：** 目錄、頁首、頁尾。

已知限制：

- 自動編號的實際數字不會輸出。標題若靠 Word 自動編號（1.1、1.2），轉出後只有標題文字。
- 註腳、尾註、註解不輸出。
- 粗體、斜體等字元格式不保留。
- 方程式不輸出。

## pptx

```markdown
## Slide 2: 開機流程

![slide-02](deck_assets/slide-02.png)

**圖中文字：** Power On、Load FW、Check CRC、Fail、Normal Mode

**連接關係：** Power On → Load FW；Load FW → Check CRC；Check CRC → Fail（推測）

**講者備註：** ……
```

規則：

1. **標題：** 每張投影片一個 `## Slide N: 標題`。隱藏的投影片照常輸出並標註「（隱藏）」。
2. **內文版面配置區：** 輸出成清單，階層用縮排表示。
3. **圖解頁的判定：** 投影片有任何線條，或有 4 個以上的自由文字圖案，就視為圖解頁。
4. **圖解頁：** 圖案文字依位置由上到下、由左到右列在「圖中文字」；連接線列在「連接關係」。
5. **連接線：** 有黏在圖案上的直接採用檔案內的紀錄。沒黏上的，看線段端點是否落在某個圖案附近（投影片寬度的 2.5% 內），並標「推測」。兩端有任一端找不到對象就不輸出，只統計數量。
6. **箭頭：** 單向箭頭 `→`、雙向 `↔`、沒有箭頭 `—`。
7. **投影片截圖：** 只有圖解頁會轉圖。透過 PowerShell 呼叫本機的 PowerPoint 匯出，只能在 Windows 執行；其他環境會警告並略過。
8. **表格、圖片、SmartArt 文字、講者備註：** 依序輸出在該投影片下。

已知限制：

- 以動畫疊層的投影片，截圖是全部疊在一起的最終狀態。
- 箭頭樣式若來自佈景主題而非線條本身，會被當成沒有箭頭。
- 旋轉過的線條，端點位置以未旋轉計算，推測可能不準。
- 圖表只標示存在，資料尚未輸出。
- 版面配置與母片上的文字不輸出。
- **圖片的相對位置不保留。** 貼在投影片上的圖片只會依序列出。一張投影片有 2 張以上圖片，或圖片與圖解混排時，腳本會印出 `[提醒]` 並列出投影片編號，建議使用者把簡報另存成 PDF 再轉；PDF 會為這類頁面附整頁截圖。

## pdf

```markdown
---
source: "sensor.pdf"
type: pdf
converter: "to-markdown 0.1.0"
mode: fast
pages: 24
pages_with_screenshot: "[3, 4, 9]"
---

# sensor.pdf

## Page 3

### 2 Sensor Specifications

（腳本抽出的段落）

| Parameter | Conditions | Value | Units |
|---|---|---|---|
| Accuracy | typ. | ±1.8 | %RH |

![圖 3-1](sensor_assets/img-004.png)

> [此頁含向量圖形，可能是圖表、方塊圖或時序圖，腳本抽取的內容可能不完整，請看整頁截圖](sensor_assets/page-003.png)
```

規則：

1. **分頁：** 每頁一個 `## Page N`，方便引用頁碼。
2. **標題：** 依字級判斷。明顯大於內文的字輸出成 `###`，略大或粗體且有編號的輸出成 `####`。
3. **段落：** 相鄰的文字行合併成段落；項目符號各自成段。
4. **雙欄版面：** 偵測到中間有空白欄時，先左欄再右欄。跨欄的標題與頁首頁尾維持整行。
5. **表格：** 只抽有框線的表格。合併儲存格依實際範圍填滿，多列表頭的處理同 xlsx。
6. **圖片：** 內嵌的點陣圖截出來存成旁檔。在三成以上頁面重複出現的同一張圖視為商標，略過。
7. **頁首頁尾：** 在三成以上頁面的上下邊緣重複出現的文字（數字不同也算同一種）會移除。
8. **目錄：** 帶點線的行各自成段，點線換成 `…`。
9. **整頁截圖：** 符合下列任一條件的頁面，視為腳本無法可靠處理，附上整頁截圖連結：
   - 沒有文字層（可能是掃描頁）
   - 文字層無法解碼
   - 內文區有大量向量圖形（圖表、方塊圖、時序圖通常是向量畫的，不是圖片）
   - 多行文字呈多欄對齊（疑似無框線表格）
   - 同一頁有 2 張以上圖片（圖片之間的位置關係只能從截圖看到）

已知限制：

- 無框線表格不會轉成表格，文字會照行輸出，只能靠整頁截圖或精準模式補救。
- 向量圖形不會單獨截出，只能看整頁截圖。實測圖多的 datasheet 約有四分之一到一半的頁面會附截圖。
- 表格儲存格內若還有小表格，小表格會在後面再出現一次。
- 每章不同的頁首（例如章節名稱）出現次數不到門檻，不會被移除。
- 跨頁的表格會被切成兩張，第二張沒有表頭。
- 方程式照文字層輸出，上下標會被攤平。
- 速度約每頁 0.3 到 0.5 秒。

相依：pdfplumber、pypdfium2（寬鬆授權）。不使用 PyMuPDF（AGPL）。

## 精準模式

對轉好的 Markdown 做後處理，五種格式共用：找出圖片連結，把圖送給看圖模型，結果插在連結後面。

```markdown
![圖 3-1](sensor_assets/img-004.png)

> [AI 描述，請對照原圖] 這是感測器的方塊圖……

> [此頁含向量圖形……，請看整頁截圖](sensor_assets/page-003.png)

> [AI 轉寫，請對照原圖]
>
> | Parameter | Value |
> |---|---|
> | Accuracy | ±1.8 |
```

規則：

1. **一般圖片：** 請模型描述圖的類型、元件關係與圖上的文字數值。
2. **pdf 的整頁截圖：** 請模型把表格轉寫成 Markdown 表格，圖表與時序圖用文字描述。
3. **pptx 的投影片截圖：** 請模型說明圖解的關係與流程，並指出腳本抽出的連接關係是否有誤。
4. **對照資料：** 同一段落中腳本已抽出的文字會一併給模型，讓它專心判斷關係，不必自己認字。
5. **快取：** 結果存在 `檔名_assets/vision_cache.json`，以圖片內容為鍵。重轉同一份檔案時，沒變的圖不會重新呼叫。
6. **略過：** 邊長小於 48 像素的圖，以及模型無法讀取的格式（例如 emf、wmf）。
7. **失敗處理：** 單張失敗只記警告；連續失敗 3 次就停止呼叫，其餘圖片保留連結但沒有描述。腳本抽取的內容不受影響。
8. **標記：** AI 產生的內容一律在引言區塊內並以 `[AI 描述，請對照原圖]` 或 `[AI 轉寫，請對照原圖]` 開頭。

API 格式：OpenAI 相容的 chat completions，圖片以 base64 放在 `image_url`。金鑰放在哪個 header、要不要加前綴，由設定檔的 `api_key_header`、`api_key_prefix` 決定。

## 舊格式（xls、xlsb、ppt、pps、doc、rtf）

不支援，也不自動轉換。遇到時腳本印出 `[需要另存]`，請使用者自己用 Excel、PowerPoint、Word 開啟，另存成 xlsx、pptx、docx 後再轉。

曾經試過由腳本呼叫 Office 自動另存，在實機上失敗，所以改成由使用者手動處理。

## 轉換方式必須先問使用者

`--mode` 是必填。沒有指定時腳本不轉檔，而是印出要問使用者的問題，以及精準方式目前能不能用，結束碼為 3。這是為了確保 AI 一定會先問，而不是自己決定。

## 驗收檢查

每次轉檔自動做：

1. **文字覆蓋：** 來源每個非空儲存格的顯示值，都必須出現在輸出裡。缺漏數量列在轉檔結果。
2. **表格形狀：** 每張表輸出的列數、欄數與偵測到的範圍一致。

需要人工或 LLM 做：

3. **十六進位與位元欄位原樣保留**（`0x1F`、`7:4`、前導零）。
4. **樣本問答：** 對轉出的 Markdown 問原檔能回答的問題，看答得出來與否。
